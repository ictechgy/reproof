# Android startup one-shot: reconstructed validation candidate

The original local-only commit `3f7c3e059ef54202005743a8d7ad3686f45cae59`
and its source bytes were unavailable after executor rollback. This proposal is
reconstructed from accessible conversation/tool history and pinned public source,
not claimed to reproduce that commit. It requires independent review of the exact activated source before
publication. Only the publisher may perform separately authorized external actions.

## Scope

One Ubuntu 24.04 job, 25 minutes, same-repository PR opened event, exact head
`codex/android-startup-one-shot-validation`, attempt 1. No push, synchronize,
dispatch, automatic retry, iOS or UI input. The authorization false barrier is removed in this candidate for the user-approved
single trial; publication still waits for final independent review. The source
pin is refreshed. This validation PR must not be merged.

Four owned runtime-fixture source files are restored byte-for-byte from public
commit `6eb207897f5819bf74b949c062a88e67df810abd`; old disabled workflows are
not copied or enabled. Production source is unchanged. The new source manifest
pins runtime/build/harness files. Only pinned Android inputs are copied into a
private build workspace, where the exact reviewed runtime-fixture include is
appended to settings. Original settings and existing causal-proof pins remain
unchanged; source/overlay/effective settings hashes are recorded.

Only owned fixture and live helper debug APKs are built. The test requires an
authenticated handshake, verified installed identity, owned target launch and
one fresh frame. No Lab input command is sent. Production startup budget and
authority semantics are unchanged. APK and evidence paths are narrowly bound to
the current run's canonical private workspace and evidence directory.

## Security and evidence

Existing read/write KVM access is required before acquisition/build/emulator
startup. Missing access stops; no unaccelerated fallback or ACL implementation
exists. No chmod, groups, udev, system settings or remote ADB changes are made.
Any later conditional security action requires separately reviewed code and
explicit authority; this draft does not implement it.

Only explicit sanitized JSON and one synthetic JPEG are uploaded for seven days.
No raw exceptions, tokens, payloads, native logs, signing keys, homes or authority
databases are retained as artifacts. Cleanup failures stay failures. Session,
helper, authority, owned forward, emulator, reaping, owned AVD and private files
are checked within their actual scope, with an always-step fallback.

Process cleanup evidence covers the owned emulator process group and supervised
tool child groups, not ownership or reaping of an ADB server that adb devices may
start. Disposable GitHub-hosted runner teardown is the backstop, not a measured
ADB-server termination assertion. No global adb kill-server is performed.
The official `actions/upload-artifact@v4` dependency is a mutable standard tag,
not claimed to be SHA-pinned.

Portable tests do not establish native/toolchain/runtime success. No remote
branch, PR, run or emulator result is implied by local preparation.
