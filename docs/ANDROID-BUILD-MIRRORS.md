# Explicit Android build mirrors (local preparation)

`python -m reproof.android_mirrors` prepares an opt-in wrapper bundle for building
Reproof's own Android helpers through operator-approved mirrors. It does **not**
execute Gradle, contact a mirror, download anything, install an APK, or modify the
source checkout. Existing direct/offline build commands and public defaults remain
unchanged. This is not an instrumentation adapter for arbitrary company builds.

Portable tests validate configuration, pins, generated bytes and local filesystem
behavior. **The generated Gradle callbacks and an actual mirrored build have not
yet been qualified by a real Gradle/Android execution.** Treat this as a reviewable
preparation adapter until that separate check succeeds in the intended environment.

## Configuration and preparation

Create a private local JSON file; do not commit real hosts or attach it to issues:

```json
{
  "schemaVersion": 1,
  "pluginRepositories": ["https://mirror.example.test/plugins/"],
  "dependencyRepositories": [
    "https://mirror.example.test/google/",
    "https://mirror.example.test/central/"
  ],
  "distributionUrl": "https://mirror.example.test/gradle/gradle-8.14.5-bin.zip"
}
```

Both repository lists are required, ordered, unique and limited to eight HTTPS
URLs. Plugins include plugin marker artifacts and the buildscript Kotlin plugin
classpath, so the selected plugin mirrors must contain both. Dependencies use only
the dependency list. There is no implicit fallback to public repositories, no
configuration discovery from imported application profiles and no environment
variable override. Credentials, query strings, fragments, percent escapes and
non-ASCII URL characters are rejected. Authenticated repositories are not supported
by this adapter; do not put passwords or tokens into these fields.

Run preparation from the checkout, with a new output directory outside `android`:

```sh
python -m reproof.android_mirrors \
  --android-root ./android \
  --config /private/local/mirrors.json \
  --output /private/local/reproof-mirror-wrapper
```

The parent of the output directory must already exist, be owned by the current
user and not be group/world writable. Inputs and their ancestors
must not be symlinks; input hardlinks, oversized files, modified pinned wrapper
files, unknown configuration keys and existing output directories are rejected.
Outputs are private (directory 0700, data 0600, executable wrapper 0700). An
incomplete write deliberately has no `READY` marker; never run a partial bundle.
Do not use a parent directory writable by other accounts. Preparation is not a
sandbox against another process with the same account's filesystem access.

The bundle includes the exact pinned wrapper JAR/scripts, copied properties with
only `distributionUrl` changed, `mirrors.init.gradle`, and a sanitized digest
manifest. The original Gradle 8.14.5 distribution SHA-256 remains mandatory and
cannot be overridden. A mirror must serve the exact same distribution ZIP. The
prepared script/properties contain the private mirror URLs: never upload the
bundle, configuration, Gradle output, or cache as public diagnostic evidence.
The manifest contains hashes/modes/sizes rather than URLs. Stdout prints only a
fixed preparation status; failures do not echo configuration values.

## Explicit execution, only after operator approval

Inspect the generated init script, wrapper properties and manifest; ensure `READY`
is present and all file hashes still match. The subsequent build is a separate
operation and can contact the configured hosts. Example for a dedicated build
workspace after the operator approves that network/build action:

```sh
export JAVA_HOME=/path/to/jdk-17
export ANDROID_HOME=/path/to/approved/android-sdk
export GRADLE_USER_HOME=/private/dedicated/gradle-home
/private/local/reproof-mirror-wrapper/gradlew \
  --project-dir /path/to/reproof/android \
  --init-script /private/local/reproof-mirror-wrapper/mirrors.init.gradle \
  --no-daemon :live:assembleDebug :driver:assembleDebug
```

Use an isolated `GRADLE_USER_HOME` so unrelated global/project-injecting init scripts
cannot conflict. The adapter does not disable such scripts, sandbox arbitrary build
code, or establish a network firewall. Gradle itself may print repository URLs on
failures; keep its logs local and sanitize before sharing. It does not configure
Android SDK package downloads or arbitrary URLs used by Gradle plugins.

## Settings and repository policy

The init script verifies the reviewed Reproof settings and root build hashes in
`beforeSettings`. At `settingsEvaluated` it replaces plugin management and dependency
repositories at settings scope and checks that `FAIL_ON_PROJECT_REPOS` remains set.
A `beforeProject` callback installs the plugin mirrors for the separate buildscript
classpath and removes subsequently added buildscript repositories. This does not
add dependency repositories at project scope or weaken `FAIL_ON_PROJECT_REPOS`.
This callback timing must be checked in the real mirrored build before declaring
corporate-network support verified. Settings plugins, composite builds and
unreviewed settings/root build changes are not accepted by the pinned adapter.

The hashes are a compatibility/trust boundary, not a whole-repository sandbox. When
Reproof updates these reviewed files, update the adapter and tests through review;
do not bypass the checks or edit pins just to get a build to run. Module sources
and normal build scripts remain trusted code in the operator's approved checkout.

HTTPS does not prove dependency equivalence. The wrapper ZIP retains its checksum,
but Maven artifacts remain governed by the project's existing dependency
verification/locks and the operator's mirror trust policy. This adapter neither
creates artifact-verification metadata nor claims mirrored dependencies equal a
previous build. Record approved mirror-policy digest and actual build provenance
for any later protected verification; this helper-preparation utility is not a
substitute for G9's approved build recipe or source identity.
