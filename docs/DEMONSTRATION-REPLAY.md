# 시연 기록 → 재현 → 자동화 생성

2026-09-09 · 플랫폼 요구사항 추가 · 구현 전 계약

사용자가 기기를 조작한 과정을 저장하고, 그 입력을 기기에 다시 실행하거나 자동화 시나리오로 내보낸다. 원격 Live의 기본 기능으로 둔다. 기존 SDK 기반 샘플 기록을 이 기능의 전체 구현으로 표현하지 않는다.

## 사용자 흐름

1. Live 세션에서 기록 시작을 누른다.
2. 사용자가 탭·길게 누르기·드래그·스크롤·키보드 입력으로 앱을 사용한다.
3. 기록 종료 후 화면과 입력이 함께 보이는 타임라인을 확인한다.
4. 전체 과정 또는 필요한 구간을 선택하고 시작 상태·기대 결과를 지정한다.
5. 재생을 실행하거나, 검토 가능한 시나리오·지원되는 자동화 스크립트로 내보낸다.
6. 버그 이슈에 연결하면 AI가 기록을 분석해 재현·수정 검증을 수행한다.

## 입력 출처와 수집 범위

| 출처 | 첫 지원 방식 | 보장 범위 |
|---|---|---|
| 웹 Live에서 사람이 조작 | 공통 제어 경로의 입력과 worker 결과를 기록 | 해당 제어 경로가 실제로 처리한 동작 |
| 휴대폰에서 사람이 직접 조작 | 앱 SDK 또는 별도 검증된 provider 기능 | 계측된 앱/화면 또는 검증된 provider 범위 |
| 스크립트·AI 조작 | 같은 입력 경로에서 actor 종류를 표시 | 실행된 명령과 관찰 증거 |

SDK 없이 원격 콘솔 입력을 기록할 수 있게 한다. 휴대폰 자체의 모든 터치가 자동으로 관측되는 것은 별개의 capability다. 이를 원격 입력 수집과 같은 기능으로 표시하지 않는다. 기존 Android/iOS SDK의 지원 범위도 그대로 명시한다.

## 기록 계약

- 원본 frame/video와 입력 event stream은 별도 artifact로 저장하고 session·frame ID·시각으로 연결한다.
- 입력에는 actor, command ID, 순서, pointer/key 상태, 위치·방향·geometry, 제스처의 시작·종료, 텍스트 참조를 기록한다.
- browser가 보낸 요청, worker가 수락한 명령, 실제 주입 결과를 구분한다. 거절된 입력을 실행된 것으로 재생하지 않는다.
- acknowledgment가 불명확한 입력은 임의 재전송하거나 완료로 가정하지 않고 불확실 구간으로 표시한다.
- 조작권 인계, 연결 해제, 회전, 프레임 유실, pointer cancel도 타임라인에 남긴다. 인증 토큰은 기록하지 않는다.
- 비밀번호·토큰 등은 저장 전에 제외하고 필요하면 실행 시 공급할 변수 참조로 바꾼다. 영상 보관·AI 전송 정책은 입력 기록과 따로 적용한다.
- 영상만으로 접촉 시각·정확한 pointer 경로를 추측해 ‘실제 입력 기록’으로 만들지 않는다. AI 추정은 별도 파생 정보다.

## 두 가지 재생 방식

| 방식 | 의미 | 검증 |
|---|---|---|
| 원본 입력 재생 | 기록된 위치·제스처·순서·타이밍을 지원 범위에서 실행 | 화면 geometry·시작 상태·provider timing 정밀도 확인 |
| 적응형 재생 | ID 또는 화면 기반 대상 인식과 명시적 대기로 같은 의도를 실행 | 원본과 달라진 입력·대기·대상 선택 근거를 기록하고 결과 별도 판정 |

입력 당시 browser 시각과 worker 처리 시각을 혼합하지 않는다. 실제 주입 시각을 관측하지 못하는 provider라면 타이밍 정밀도를 제한해서 표시한다. 타이밍 의존 버그를 적응형 대기로 바꾸면서 같은 재현이라고 주장하지 않는다.

기록은 불변으로 보관하고 편집본·생성 스크립트는 파생 artifact로 만든다. 각 실행 단계는 원본 event ID에 연결한다. AI가 자동으로 정리한 클릭·대기는 검토 가능한 차이로 표시하며 사용자 동작을 조용히 지우거나 추가하지 않는다.

## 시작 상태와 편집

구간을 잘라내면 그 이전의 로그인·화면 이동·데이터 변경이 빠질 수 있다. 선택 구간만으로 시작할 수 없으면 필요한 앞부분을 포함하거나, 검증된 fixture/checkpoint에 연결하거나, 재현 불완전 상태로 남긴다. 사용자의 앱 데이터를 임의로 초기화하지 않는다.

편집기는 단계 삭제·구간 선택·값 변수화·대기·assertion 추가를 제공할 수 있다. 초기 구현은 타임라인 검토와 전체 구간 재생부터 시작한다. 인증·lease 정보는 새 실행에서 새로 발급하고 원본 세션의 권한을 재생하지 않는다.

스크립트 내보내기는 우선 자체 시나리오 형식으로 제공한다. Appium/WebDriver 계열 코드는 검증된 호환 명령만 출력하고, 미지원 입력이 있으면 손실 없이 표현할 수 없음을 표시한다.

## 완료 기준과 단계

P0에서 event/frame/입력 결과 연결 형식을 설계하고, P1의 Android Live 한 대 단계에 기본 동작 기록·재생을 포함한다. P4에서 자동화 형식 내보내기, P5에서 AI 보조 변환·적응형 재생·이슈 연결을 확장한다.

첫 완료 기준은 사용자가 원격으로 시연한 지원 동작을 절차 재입력 없이 저장하고, 같은 시작 조건에서 입력 순서를 보존해 다시 실행하는 것이다. 탭, long press, drag, scroll, 텍스트 commit을 포함하고, 중복 입력·누락된 up/cancel·방향 변경·연결 해제·불명확한 acknowledgment를 실패 사례로 검사한다.

동작 재생 성공, 같은 화면/상태 도달, 원래 결함 재현은 각각 다른 판정이다. 최종 버그 재현과 AI 수정 성공은 기존의 독립 oracle·반복 검증·artifact 보호 규칙을 적용한다.
